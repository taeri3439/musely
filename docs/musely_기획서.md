# musely — 기획서

제품 정의 · 유저 플로우 · 화면 구성

> 관련 문서: **빌드 플랜**(전체 구조), **ai-core 플랜**(AI 서비스 상세)

---

## 01. 제품 정의

### 한 줄

> 내 피부 타입과 향 취향을 한 번 등록해두면, 화장품과 향수를 **이유와 함께** 추천받는 서비스.

### 해결하려는 문제

화장품을 고를 때 사람들이 실제로 겪는 건 "좋은 제품을 모르는 것"이 아니라 **"내가 피해야 할 게 뭔지 모르는 것"**이다. 알코올이 안 맞는데 성분표를 일일이 읽기 번거롭고, 레티놀을 쓰는 중인데 새로 산 각질 제거제와 같이 써도 되는지 헷갈린다. 향수도 마찬가지로 "우디 계열이 좋다"까진 아는데 그다음이 막힌다.

musely는 **제약 조건을 먼저 지키고, 그 안에서 추천하고, 왜 그런지 설명하는** 순서로 이 문제를 다룬다.

### 차별점

| 일반적인 추천 서비스 | musely |
|---|---|
| 인기순·평점순 목록 | 내 제약 조건을 통과한 것만 |
| "이 제품 좋아요" | "이 성분이 없어서 골랐어요" |
| 주의사항 없음 | 현재 쓰는 성분과의 조합 주의 안내 |

### 타깃

20~30대, 스킨케어에 관심은 있지만 성분표를 해석하기는 번거로운 사람. 특히 "레티놀은 쓰는데 같이 쓰면 안 되는 게 뭔지" 수준의 반쯤 아는 상태.

---

## 02. 핵심 원칙 (화면 설계의 기준)

1. **제약은 타협하지 않는다** — 기피 성분이 들어간 제품은 어떤 경우에도 결과에 나오지 않는다. 조건에 맞는 게 없으면 "없다"고 말한다.
2. **단정하지 않는다** — "이 제품이 좋아요"가 아니라 "이런 이유로 맞을 수 있어요". 의학적 효능을 단언하지 않는다.
3. **기다리는 시간을 숨기지 않는다** — 5~10초 걸리는 걸 스피너 하나로 때우지 않고, 지금 무슨 단계인지 보여준다.
4. **근거를 항상 같이 준다** — 모든 추천 항목에는 왜 뽑혔는지 한 줄이 붙는다.

## 03. 정보 구조 (IA)

```
musely
├─ 프로필
│   ├─ 피부 정보 (타입 / 고민 / 기피 성분 / 사용 중인 성분)
│   └─ 향 취향 (선호 계열 / 사용 상황)          ← 건너뛰기 가능
├─ 추천받기
│   ├─ 진행 중 (폴링)
│   └─ 결과
│        ├─ 화장품 추천
│        ├─ 향수 추천
│        └─ 주의사항
└─ 히스토리
     └─ 지난 추천 상세
```

## 04. 유저 플로우

```
 [시작]
   │
   ▼
 프로필 입력 ──── 향 취향 건너뜀 ──┐
   │ (둘 다 입력)                 │
   ▼                             ▼
 추천 종류 선택               화장품만 추천
 (화장품 / 향수 / 둘 다)          │
   │                             │
   ▼                             │
 추천 진행 화면 (5~10초 폴링) ◄────┘
   │
   ├── 성공 ──► 결과 화면 ──► 피드백 ──► 히스토리에 저장
   │
   ├── 조건에 맞는 제품 없음 ──► 조건 완화 안내 + 프로필 수정 유도
   │
   └── 실패(타임아웃/오류) ──► 재시도 버튼
```

**재방문 플로우** — 프로필이 이미 있으면 첫 화면이 바로 "추천받기"가 된다. 프로필 재입력을 요구하지 않는다.

## 06. 화면 2 — 추천 진행 (폴링)

**이 화면이 이 프로젝트에서 제일 신경 써야 할 화면이다.** 5~10초를 스피너 하나로 버티게 하면 체감이 길어지고, 사용자는 멈춘 줄 안다.

### 레이아웃

```
┌──────────────────────────────────────────┐
│                                          │
│           ◐  추천을 만들고 있어요           │
│                                          │
│   ✓  프로필 분석                          │
│   ✓  조건에 맞는 제품 찾기                  │
│   ◐  성분 조합 검수 중...                  │
│   ○  추천 이유 작성                        │
│                                          │
│   ▓▓▓▓▓▓▓▓▓▓▓▓░░░░░░░░  약 3초 남음        │
│                                          │
│                  [취소]                   │
└──────────────────────────────────────────┘
```

### 동작

- 1초 간격으로 `GET /api/recommendations/jobs/{jobId}` 폴링
- 응답의 `status`와 `trace`로 단계를 갱신 (ai-core가 넘겨주는 `trace` 활용)
- 60초 경과 시 폴링 중단 → 타임아웃 화면 전환
- 단계 문구는 사용자 언어로. "ingredient_matcher 실행 중" 같은 내부 이름을 그대로 노출하지 않는다

### 상태

| 상태 | 화면 |
|---|---|
| RUNNING | 위 단계 표시 |
| DONE | 결과 화면으로 자동 전환 |
| FAILED · TIMEOUT | "시간이 오래 걸리고 있어요" + [다시 시도] |
| FAILED · 그 외 | "문제가 생겼어요" + [다시 시도] + 오류 코드 작게 표기 |
| 취소 | 프로필 화면으로 복귀 (진행 중 job은 그냥 버린다) |

### 구성 요소

| 영역 | 내용 | 데이터 |
|---|---|---|
| 요약 | 2~3문장, 어떤 기준으로 골랐는지 | `summary` |
| 주의사항 | 조합 주의 카드 (없으면 영역 자체를 숨김) | `cautions[]` |
| 제품 카드 | 이름 / 브랜드 / 카테고리 / 점수 / 추천 이유 | `items[]` |
| 피드백 | 좋아요·아쉬워요 2버튼 | `POST /api/feedback` |

**제품 카드의 "추천 이유" 한 줄은 필수다.** 이게 빠지면 그냥 목록이 되고, 이 서비스의 차별점이 사라진다.

### 주의사항 카드의 표기 규칙

- `severity: avoid` → 빨간 계열 + "피하세요"
- `severity: caution` → 노란 계열 + "주의"
- `source`와 `confidence`를 반드시 같이 표기. 근거 없는 단정으로 보이지 않게 하는 장치

### 상태

| 상태 | 화면 |
|---|---|
| 정상 | 위 레이아웃 |
| `relaxationLevel > 0` | 상단에 "조건에 딱 맞는 게 적어서 일부 조건을 완화해서 찾았어요" 안내 배너 |
| 결과 0건 | "조건에 맞는 제품을 찾지 못했어요" + 어떤 조건이 걸렸는지 표시 + [조건 수정하기] |
| 향수 미입력 | 향수 섹션 자체를 렌더링하지 않음 (빈 영역을 남기지 않는다) |

## 09. 카피 톤 가이드

| 상황 | ❌ 이렇게 쓰지 말 것 | ✅ 이렇게 |
|---|---|---|
| 추천 이유 | "트러블에 효과적입니다" | "진정 성분 위주라 트러블 고민에 맞을 수 있어요" |
| 주의사항 | "함께 쓰면 안 됩니다" | "함께 쓰면 자극이 누적될 수 있어요. 번갈아 쓰는 걸 권해요" |
| 결과 없음 | "검색 결과가 없습니다" | "조건에 맞는 제품을 찾지 못했어요. 기피 성분을 조금 줄여볼까요?" |
| 오류 | "500 Internal Server Error" | "문제가 생겼어요. 잠시 후 다시 시도해주세요" |
| 로딩 | "Loading..." | "조건에 맞는 제품을 찾고 있어요" |

**원칙**: 단정하지 않기 · 내부 용어 노출하지 않기 · 실패했을 때 다음 행동을 알려주기.

## 10. 비기능 요구

- **반응형** — 모바일 우선. 카드 리스트는 모바일 1열, 데스크톱 2열
- **폴링 상한** — 프론트 60초, 그 이후 자동 중단하고 타임아웃 화면
- **에러 코드** — 백엔드가 주는 `error.code`로 분기하되, 사용자에게는 위 톤 가이드대로 번역해서 보여준다
- **접근성 최소선** — 버튼에 명확한 레이블, 색상만으로 상태 구분하지 않기(주의 배지에 텍스트 병기)

---

## 11. 하지 않는 것 (Non-goals)

이번 범위에서 **의도적으로 빼는 것들**. 나중에 하고 싶어질 때 이 목록을 다시 볼 것.

- 소셜 로그인, 비밀번호 재설정 — 이메일 기반 최소 인증만
- 제품 구매 연동, 가격 비교, 재고 조회
- 사용자 리뷰 작성 및 공개
- 관리자용 카탈로그 관리 화면 — **API만 만들고 시드 데이터는 스크립트로 넣는다**
- 피부 사진 업로드 및 이미지 분석
- 알림, 이메일 발송
- 추천 결과 공유 기능
